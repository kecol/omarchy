## Interpretation

- **Workflow check**: rejects a request through a particular Omarchy entrypoint. It is not an operating-system restriction on every process owned by the user.
- **Runtime constraint**: concrete launch arguments request filesystem, capability or resource restrictions from Podman/the kernel. This review did not exercise their enforcement.
- **Preference / launch friction**: chooses a future launch route or blocks selected PATH lookups. It does not confine arbitrary execution.
- **Observation / admission gate**: consumes metadata or diagnostic results to permit/refuse a start. Its visibility and input trust limit its conclusions.

The trusted inputs include installed Omarchy code, current-user configuration, the local task registry and the container engine. These wrappers do not establish a separate trusted-controller identity against a malicious host process with the same user's permissions. Prompt instructions, labels and planning documents are not equivalent to runtime enforcement.

## Identity, terminal attachment and closure

Boot identity, process start ticks, current-user ownership, namespaces and immutable container IDs reduce stale-target mistakes. They do not authenticate an executable's provenance or prove that a human physically approved an operation. ## Proposed layer classification

This task 2.1 classification describes architectural responsibility in the inspected checkout. It is not an exhaustive upstream-diff census or a claim that every line in a shared file is unchanged upstream. No new upstream revision was fetched or compared. A row can span more than one layer; splitting a file by its name alone can remove a necessary check or expose data to a broader caller.

| Layer | Responsibility | What the label does not mean |
| --- | --- | --- |
| **U — upstream desktop base** | General shell/plugin hosting, bar/terminal dispatch, menu parsing and shell/tool startup mechanisms consumed by the fork. Existing authentication/service-access hardening and other unclassified safety patches remain preserved. |
| **S — safety enforcement** | Existing checks, constrained execution, credential handling, state ownership and identity-sensitive operations that protect the named workflow. ## Findings to retain for future implementation review

1. Managed task clones and ad-hoc Container project binds protect different resources. Preserve that distinction when describing or extracting the safety layer.
2. Keep mode/definition re-read and concurrent-start limitations visible. A sequence of checks is not an atomic admission lease.
3. Patch construction is working-tree-versus-HEAD, and apply does not require an approved candidate digest. Do not import the stronger draft promotion contract as an existing guarantee.
4. PATH friction, image labels, registry state and status observations must not be renamed as confinement or authentication proofs.
5. Startup audit visibility can be incomplete; source and resource labels need to remain distinguished from actual runtime measurements.
6. Recipe reuse, new-image verification and tag promotion have different failure/rollback scopes. Do not assume every failure leaves every tag untouched.

7. Host subscription accounts intentionally share history/settings; managed assignment, ad-hoc harness and editor workspace homes have different persistence/sharing scopes. Do not call all of them independent sessions.
8. Exact-instance close, overview TERM-only stop and legacy task/workspace/audit stops have different target validation, confirmation and escalation contracts.
9. The original inventory found inconsistent local-engine selection. The approved scoped routing correction and its fixture/named native evidence are recorded above; they do not certify every entrypoint/configuration/version. Rootless detection, omitted socket mounts and bounded metadata queries still do not establish universal engine-access denial.
10. Overview metadata observation must remain distinct from authentication-panel streams, usage refreshes and explicit credential export/import. OpenShell prototypes must not be presented as ordinary managed-task enforcement.
11. CLI/default-agent/per-launch selection, the two menus and the widget click targets have distinct confirmation, side-effect and file-sharing contracts. Preserve them even when they are not new containment mechanisms. Reusing workspace files is not a new private clone or an editor-container attachment.

These findings are source observations and limits, not newly reproduced runtime defects. The evidence map identifies existing check mechanisms and historical scopes; it does not establish a new test pass or runtime qualification. No fixes, policy changes, new test campaign or extraction are authorized by recording them.
