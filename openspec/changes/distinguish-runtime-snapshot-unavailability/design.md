# Design

## Context

See [proposal.md](proposal.md) for motivation and [managed-runtime-availability](specs/managed-runtime-availability/spec.md) for the proposed behavior contract. The change is security-relevant and affects a shared producer with ten direct callers, so a design is required.

At the source base, the producer explicitly requested the local engine but still printed `[]` and exited successfully if Podman was missing or `info` failed. Enumeration runs in process substitution consumed by `mapfile`, which does not propagate the child failure. Inspection/projection streams directly to stdout, so a failing producer can emit data before its final pipeline status is known. Most callers use checked assignments or `pipefail`; archive additionally ignores nested cleanup failures with `|| true`.

Configured agent listing combines definitions and mode with observed running counts. Runtime ps/inspect/task-status depend on a successful snapshot. Inspect reaches registry history only after finding no active match; an unavailable observation must not be used as that decision.

## Goals / Non-Goals

**Goals:** expose query failure as unavailable, preserve successful array consumers, make dependent safety actions refuse uncertainty, and retain configured-agent information without fabricated runtime counts.

**Non-Goals:** new admission leases, immutable-target stop controllers, a complete audit of labels or same-user authority, retries, remote fallback, production engine/service operations, new query deadlines or a generic snapshot framework. Native Podman integration must be checked in a disposable VM; that bounded evidence does not prove containment or repair unrelated state/cleanup policies beyond propagating a nested cleanup failure.

## Decisions

### Producer protocol and publication

Keep the hidden producer's successful interface: exit 0 and one projected JSON array. Reserve exit 2 for detected observation unavailability, with no stdout payload and a fixed stage-specific stderr diagnostic. Missing Podman, failed readiness/enumeration/inspection, malformed responses, incomplete inspection and failed projection all use that path. Do not forward raw engine/jq error text containing paths or untrusted metadata. Other unexpected command failures must remain errors, not be silently classified as an empty inventory.

Capture and check each stage explicitly. Replace enumeration process substitution with a checked capture before populating the ID array. Only a successful truly empty enumeration produces `[]`; failure after output must discard that output. Request nontruncated IDs and validate full container-ID lines before using them as argv. Reject malformed/duplicate ID lines rather than executing ambiguous inputs.

For nonempty enumeration, capture inspection before projecting. Require one JSON document with an array of engine records, object structure for the fields the projection consumes, unique IDs and exact correspondence to the enumerated set. Missing, duplicate, unexpected or disappearing containers make this observation unavailable. Labels that are optional in the existing projection remain optional; do not turn this into a new agent-definition or security-policy validator. Preserve the existing projection fields and successful inspection-record order. Buffer and check projected JSON before printing it, so a later failure cannot publish a partial successful-looking array.

A new top-level envelope would require rewriting every array consumer and is not needed. Continuing to print `[]` with a failure status would leave data that careless callers can treat as valid; the no-payload failure channel avoids that ambiguity. A process-execution deadline is a separate policy decision: this change handles reported failures and invalid results, not a hung engine that never returns.

Configured-list JSON remains an array. Each record gains `runtime_available`; `running_instances` changes from a number to number-or-null. This is a compatibility change, not permission to coerce null back to zero. Keep definition identity, sorting, configured/effective mode, source and other fields unchanged. Do not add a UI, polling service, new command or persistent availability flag.

Archive cleanup remains sequential. Replace ignored cleanup results with explicit checked control flow, retaining the child's force argument and surfacing failure before the final task-status update. Earlier assignments can already be cleaned when a later one fails; report that partial outcome and leave the task unarchived. Do not recreate deleted directories, guess completion, continue automatically or claim transactionality.

### Relationship to the previous routing change

The completed local-engine change deliberately preserved empty-success as a non-goal and its delta scenario records that historical scope. This proposal deliberately supersedes that failure-policy exception; explicit locality and no remote retry remain required. Do not revise the old evidence or treat its fixture results as proof of the new availability contract. Main specs are currently empty; this new capability records only the proposed availability behavior, not a complete runtime model. Any later combined spec synchronization must retain this prospective distinction instead of publishing contradictory preserved-empty behavior as current policy.

## Risks / Trade-offs

- Engine absence now blocks runtime-dependent operations → document the intentional distinction and retain configured listing with explicit unknown counts.
- A container disappears between enumeration and inspection → refuse that observation conservatively; do not retry or advertise a complete inventory. Observation/action races remain.
- Null counts break numeric-only clients → document the changed JSON type and availability field; do not hide uncertainty behind zero for compatibility.
- Archive fails after earlier cleanup succeeded → report partial progress and retain registry truth; no automatic rollback or resume is promised.
- New validation rejects synthetic or unexpected engine shapes → align fixtures with the engine response contract and require the targeted native VM compatibility cases before integration. Attempt 06 supplies passing evidence for those named integrations only; new versions or covered source changes require affected revalidation. Stop if the bounded validation requires a wider API/transport redesign.
- An engine process hangs → existing absence of producer deadlines remains explicit; fixture run limits are not production query deadlines.

## Migration Plan

No state conversion, service restart, host engine configuration edit, shipped image rebuild or migration belongs to the source implementation. Deliver the availability repair and approved child-local routing correction with their associated fixtures/docs coherently in the non-dev-linked candidate. Document the compatibility changes in managed-agent and affected CLI references, including force and partial-archive behavior.

Integrate the reviewed candidate into the active dev-linked checkout only after focused checks, native VM assertions/cleanup and PR/CI results have been reviewed and integration has separate approval. Confirm the integrated runtime/test content matches the tested content and verify command resolution. Updating this active checkout is activation for subsequent CLI invocations even without an installation command or restart; do not report such integration as source-only/no activation. No reboot is required for these scripts, and existing agent/container processes are not restarted. Changing the dev-link target itself has a separate session/reboot contract and is not proposed here.

Before integration, rollback means retaining or discarding only the owned inactive candidate changes after review. After integration, restore the reviewed availability and child-routing delta with its associated fixtures/docs coherently from the pre-change revision under separate approval; that restoration also affects subsequent invocations immediately. Keep the preceding commit's explicit local option, while recognizing that rolling back the follow-up also restores its named-connection-selector gap. Do not reset unrelated work, alter task/workspace state, restore deleted user directories automatically or erase partial cleanup records. Rollback restores the known false-empty, ignored-cleanup and ambient-selector weaknesses and must be reviewed accordingly. No commit, publication, integration, rollback or archive is authorized by task status.
